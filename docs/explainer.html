Code Gym

Notes you can redo.

You learn a concept and write annotated code about it. Reading it again later teaches little. Code Gym turns that note into a drill with gaps, so next time you write the code instead of re-reading it, and it keeps a record of how much help you needed.

Rules the generator follows


  
    
    
  • 3 to 6 Todos, ordered so each builds on the one before. Each is a coherent chunk (a type, a function), never a single token.
    • 
    
  • Marker format: a one-line comment containing TODO-NN: title, followed by three empty lines.
    • 
    
  • Imports and usage lines from the Note stay in the Scaffold, so the reader knows what must compile.
    • 
    
  • A Hint names the concept, never the code. The Soal contains no solution code.
    • 
    
  • Splicing every Solution under its marker must produce a complete, compiling file.
    •

How the active Todo and your answers are found


  
Four pure functions in src/practice.ts do everything. The demo above runs JavaScript ports of them.

  

    
  

  
    
    
  • parseMarkers: every line matching TODO-(\d\d) is a marker; the title is the text after the colon.
    • 
    
  • extractRegions: the lines after a marker up to the next marker (or end of file), trimmed. That is your answer for that Todo.
    • 
    
  • activeTodo: nearest marker at or above the cursor line; TODO-01 if the cursor is above all markers.
    • 
    
  • spliceSolution: replace each region with its Solution. The full solution is always derived, never stored.
    • 
  

  
Because answers are found by marker position, you can write anything in a region, and the markers must stay in place.








Why keep every Attempt


Each submit records, per Todo, whether you used the hint and whether you revealed the solution. Redo the same Practice a few days apart and the pattern shows what has actually stuck.

What an Attempt file holds



practices/generics/attempts/practice-generics-01.json
{
  "slug": "generics",
  "attemptNo": 1,
  "submittedAt": "2026-11-03T14:00:00.000Z",
  "code": "<full editor contents>",
  "todos": [
    { "id": "TODO-01", "answer": "<your region>", "hintUsed": true, "revealUsed": false }
  ]
}

  
Numbered per Practice (01, 02, …), plain JSON, committed to git with everything else.








Deliberately small


A single-user local tool: one Bun process serves the API and the React client on one port. The judgement of "did I get it" is you reading the diff.

Vocabulary


  

    
Note
markdown of annotated snippets about one concept; the generator's input

    
Practice
the bundle generated from one Note

    
Soal
what the finished Scaffold must achieve

    
Scaffold
the incomplete code you fill in

    
Todo
one numbered gap; has one Hint and one Solution

    
Hint
a nudge that does not contain the code

    
Solution
the code that completes one Todo

    
Attempt
one submitted fill, with hint/reveal usage
